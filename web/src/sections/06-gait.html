06

Gait & Model Predictive Control

步态与 MPC：从 ZMP 到预测控制

上一章的全身控制每毫秒算一次力矩，却不知道脚下一步落在哪。这一章补上那一步：用线性倒立摆把平衡压成两个状态，用零矩点和捕获点决定落点，再用 1.6 s 的凸模型预测控制（model predictive control, MPC）把两者接成滚动优化。

05 章的 QP 每秒解 1000 次，但它只回答一个问题：这一毫秒，30 个关节各出多少力矩。它不知道脚下一步该落在哪、什么时候落。这不是遗漏，是时间尺度不匹配——全身控制（Whole-Body Control, WBC）的决策周期是 1 ms，落脚的决策周期是 0.3–0.8 s，跨三个数量级。

代价可以用一个数说清。质心高 0.8 m 的双足，ω = √(9.81/0.8) = 3.50 rad/s。质心偏离支撑点 1 cm、初始速度为零，1 s 后偏离 16.6 cm（cosh 3.5）；如果初始速度刚好对上发散模态，同样的 1 cm 会放大成 33 cm（e3.5）。任何以毫秒为单位的反馈都追不上这个指数；唯一的办法是在误差还小的时候，用更长的视界决定下一步落在哪。

步态相位：占空比是一条分界线

这一节解决什么问题：把「走路」拆成可以数清的相位，说清每个时刻有几只脚在推地。

双足的一个步态周期只有三种相位：双支撑（double support，两脚同时着地）、单支撑（single support，只有一只脚着地）、摆动（swing，一只脚在空中）。相位决定两件事：支撑多边形有多大，ZMP 能放在哪；接触力能施加在哪几个点上。这两件事直接变成下一层优化的约束，所以相位不是描述，是输入。

占空比（duty factor）是一脚着地时间占步态周期的比例，记作 β。以 1.25 Hz、周期 0.8 s 为例：β = 0.65 时每只脚支撑 0.52 s、摆动 0.28 s，两脚同时着地的重叠是 2×0.52 − 0.8 = 0.24 s，占周期 30%，分成两段各 0.12 s。β = 0.35 时每只脚支撑 0.28 s，两脚都不在地上是 0.8 − 2×0.28 = 0.24 s，同样是 30%。同一个 30%，在走路里是双支撑，在跑步里是腾空（flight phase）。β 跨过 0.5 就换了物理：走路任何时刻至少一只脚能推地，跑步有一段时间一只脚都不能。

这解释了走路为什么有速度上限。平均速度是步长除以单步周期：v = S/Tstep = 2S/Tcycle，Tcycle 是一个完整周期（左右各一步），表 6.1 里的 T 用的就是它。1.3 m 高的机器人腿长 0.65 m，步长做到 0.5 m 已经很勉强；要在 β > 0.5 下跑到 2.5 m/s，需要 Tstep = 0.2 s，也就是每秒 5 步、完整周期 0.4 s——摆动腿得在 0.2 s 内完成抬起、前摆、落地，关节峰值角速度 10 rad/s 量级。ASIMO 2011 版标称 9 km/h（2.5 m/s），那是跑步步态，靠腾空把 1/Tstep 提上去，不是把走路调快。

线性倒立摆：把整机压成两个状态

这一节解决什么问题：给一个只有两个状态、却能在 1 ms 内预测 1 s 之后质心位置的模型。

三个假设：质心高度恒定为 zc；腿无质量；地面反力的合力通过支撑点（点足）。把这三个假设代进去，对支撑点 p 取矩。水平方向上只有地面反力一个外力，由牛顿第二定律它等于 m c；竖直方向上重力与反力大小相等、方向相反。取矩时地面反力过 p 点、力臂为零，只剩两项：重力作用在质心上、水平方向偏出 (c − p)，力矩是 m g (c − p)；质心的水平加速度 m c 发生在高度 zc 上，对应绕 p 的角动量变化率 m c zc。两者相等——注意这不是「合力矩为零」，而是「重力矩正好推动质心继续往外倒」，c 越偏，加速度越大，所以它不稳定。约掉 m 与 zc，得到线性倒立摆模型（Linear Inverted Pendulum Model, LIPM）：

c=ω²(c−p),　ω=√(g / zc) 6.1

其中 c 是质心水平位置，p 是零矩点水平位置，ω 是倒立摆的自然频率。记法先交代清楚：字母上一个点表示对时间的一阶导数，即速度；两个点表示二阶导数，即加速度——所以 c 是质心速度、c 是加速度，本章后面一直用这套记法。zc = 0.8 m 时 ω = 3.50 rad/s，时间常数 1/ω = 0.29 s，摆动周期 2π/ω = 1.79 s。

直觉很清楚：这就是一根倒立摆，支点在脚，质量压在 0.8 m 高处。唯一的平衡点是 c = p，而且不稳定。质心偏 1 cm、初始速度为 0，cosh 给出 0.29 s 后 1.5 cm、0.58 s 后 3.8 cm、1 s 后 16.6 cm；同一个初始偏差换到捕获点坐标下是 2.7 / 7.4 / 33 cm（见后面的「捕获点」一节），差的只是一个 e−ωt 的收敛模态。它坏掉的原因不是增益没调好，是指数本身——任何有限带宽的反馈都追不上 eωt。

c(t)=p+(c0−p)cosh(ωt)+(c0/ω)sinh(ωt) 6.2

cosh 与 sinh 是指数发散的对称写法，定义是 cosh x = (ex + e−x)/2、sinh x = (ex − e−x)/2：两个指数一个涨一个落，相加得双曲余弦，相减得双曲正弦。ωt = 1 时 cosh = 1.54、sinh = 1.18。6.2 式就是 c = ω²(c − p) 在给定 c0、c0 时的解：把 t = 0 代进去得 c(0) = c0，对时间求导后得 c(0) = c0。这个闭式解的工程价值在于：给定当前 (c, c)，任意时刻的位置可以直接算出，不需要积分，也不需要迭代。

为什么这个粗暴简化极其有用，有三条理由。第一，只剩两个状态，而且控制量 p 线性进入，预测 1.6 s 只是一串线性等式，能塞进凸 QP 并在 1–5 ms 内解完。第二，它保留了唯一危险的方向——+ω 特征值；腿的摆动、上身角动量、关节柔度都是更高频、更小幅度的次要项。第三，算错的部分有兜底：1 kHz 的 WBC 用全模型把残差吸收掉。

这是一笔时间尺度上的交易：上层用错模型，换 100 倍的规划速度。代价也要说清。zc 恒定意味着它描述不了上下起伏，跑步和上下楼梯必须换模型；腿无质量意味着它不知道摆动腿的惯性力，快速摆腿时这一项能到体重的 10–20%（量级估计）。

图 6.2b 把这个不稳定过程动起来：支撑点固定，质心沿摆杆绕支撑点缓慢摆动——倾角越大，质心偏移越大，而偏移正是 LIPM 方程里驱动加速度的那一项。速度箭头的方向提示「现在朝哪儿走」，地面投影点的左右漂移是位置状态 c 的直观映射。

零矩点：支撑多边形里的一个点

这一节解决什么问题：给出一个能画在脚底、能写成线性约束的几何量。

零矩点（Zero-Moment Point, ZMP）是地面上使地面反力合力矩的水平分量为零的点。把 LIPM 的加速度代回去，得到它的等价定义：

p = c − (zc / g) c = c − c / ω² 6.3

读法是：ZMP 是质心加速度的反作用点。质心往前加速，ZMP 必须往后挪；质心要减速，ZMP 往前挪。所以所有 ZMP 步态生成器都有同一个结构——先规划 ZMP，再反解质心，脚先动、质心后动。

没有角动量时，ZMP 与压力中心（Center of Pressure, CoP）重合；有上身或飞轮角动量 L 时，两者差 L / (m g)。ASIMO 挥手臂时这个差值是几毫米到几厘米（量级估计），所以工程上用足底力传感器测 CoP，而不是解析算 ZMP。

支撑多边形（support polygon）是接触点的凸包：单脚支撑时是脚掌轮廓（约 0.24 m × 0.10 m），双支撑时是两只脚的凸包。ZMP 落在内部，等价于存在一组非负的地面反力能实现它；落在外面，等价于需要脚去「抓」地面——物理上不存在。

踝关节的权限可以算出来。要把 ZMP 推到脚掌前部，踝需要力矩 τ = Fz·d，于是最大偏移 d = τ/(m g)。60 kg 整机、踝 59 N·m（H1 量级）给出 d = 0.10 m，对应质心加速度 ω²×0.10 = 1.2 m/s²，约 0.12 g。靠踝关节你只有 0.12 g 的水平加速度权限，再多就必须换支撑点。这是「为什么必须迈步」的定量版本，也解释了为什么脚小的机器人走不快。

ZMP 有三个局限。腾空时它不存在——没有地面反力就没有 ZMP，跑步和跳跃要换模型。它不给力矩——ZMP 是运动学等效点，变成 30 个关节的力矩还要一步逆解。它是二阶微分——1 mm 的位置噪声在 1 kHz 采样下被放大到 1 mm/(1 ms)² = 1000 m/s² 量级，所以实机不微分，直接用六维力传感器测 CoP。

警告 Warning

「ZMP 出了支撑多边形就一定会摔」是错的。出界只说明当前这一步的接触维持不住；只要下一步能落到捕获点附近，机器人可以救回来。把 ZMP 当稳定判据的控制器，会在最该迈步的时候选择刹车，然后在原地倒下。

捕获点：把速度误差兑换成落点

这一节解决什么问题：把「要不要迈步、迈到哪」变成一个闭式公式。

定义发散运动分量（Divergent Component of Motion, DCM）：

ξ = c + c / ω,　ξ = ω (ξ − p) 6.4

直觉是把 (c, c) 分解成两个模态：一个按 e−ωt 收敛，记作 χ = c − c/ω；一个按 e+ωt 发散，就是 ξ。收敛的那个不用管，发散的那个必须处理。ξ 的单位是米，可以直接画在地面上，这是它比 (c, c) 好用的原因。

关键性质：如果 p = ξ，那么 ξ = 0，发散停止，质心渐近收敛到 ξ。所以 ξ 就是「脚踩这里就能停住」的位置，也就是捕获点（capture point）。

数值。被推一下，速度突变 Δv，捕获点前移 Δv/ω。Δv = 0.2 m/s 时前移 5.7 cm，还在脚掌 ±0.12 m 的范围内，踝关节就能吸收，不用迈步。Δv = 0.5 m/s 时前移 14 cm，超过脚掌，必须迈一步。40 N·s 的冲量（一个 4 kg 的球以 10 m/s 撞上来）给 60 kg 的机器人 0.67 m/s，前移 19 cm。所以「被推一下能站住」靠的不是腿更有力，而是把落点挪到 ξ。

落脚点策略可以写成一行：pnext = ξ − b。为什么不直接落在 ξ 上？因为落在 ξ 上，ξ 相对新脚变成 0，机器人停住，下一步就不走了。要维持速度，脚要落在 ξ 后面一点点，这个偏置由期望步长 Sd 决定：b = Sd / (eωT − 1)。分母是推出来的：落点退后 b，一步之后 DCM 相对新脚的偏差就被放大成 eωT·b；稳态下这一步要前进 Sd，于是 eωTb − Sd = b，整理即 b(eωT − 1) = Sd。ω = 3.5、单步周期 T = 0.625 s（1.6 步/秒）、Sd = 0.35 m 时 b = 0.044 m，落脚点要在捕获点后方 4.4 cm。

这个数小得刺眼，也说明捕获点落脚为什么难：落点差 1 cm，一步之后 DCM 就多差 7.9 cm（放大 eωT − 1 = 7.9 倍）。步频降到 1.25 步/秒（T = 0.8 s），eωT = 16.4，同样的 1 cm 变成 15 cm。这就是「步频高更稳」的定量解释——不是玄学，是指数增益变平。

落脚点规划：Raibert 启发式与三条硬约束

这一节解决什么问题：从「这一步落在哪」扩展到「一串落脚点怎么排」。

Raibert 在 1986 年给出的启发式到今天还在用：

xf = c·T/2 + k(c − cd) 6.5

第一项是中性点：以当前速度，T/2 之后质心会走到哪。第二项补偿速度误差，k 的量纲是秒，实机常用 0.03–0.1 s。代入一组数：T = 0.5 s、c = 1.0 m/s、cd = 1.2 m/s、k = 0.05 s，得 xf = 0.25 + 0.05×(−0.2) = 0.24 m。速度掉到 0.8 m/s 时 xf = 0.20 − 0.02 = 0.18 m，脚自动往前收 6 cm，机器人减速。这就是「刹车」在落脚点层面的实现。

它与捕获点是同一个思想的两副面孔：cT/2 是 ξ 在 ωT 很小时的泰勒展开首项。前者是工程启发式，后者是解析判据；实机上两者常常混用——用 DCM 算目标，用 Raibert 的增益调手感。

三条硬约束决定步长能有多大。几何：落脚时髋到脚的距离不超过 0.95 倍腿长；1.3 m 机器人腿长 0.65 m，步长 0.5 m 时髋脚水平距离 0.25 m，腿与竖直夹角 23°，还留得住；步长 0.7 m 时夹角 33°，膝要弯更多，力矩跟着涨。时间：摆动腿要在 Tswing 内完成抬起、前摆、落地；T = 0.4 s、Tswing = 0.18 s 时摆腿平均角速度约 2.5 rad/s、峰值 5 rad/s 量级。序列：相邻两步的落点差受髋关节行程限制，双支撑时两脚横向间距超过 0.3 m 就会自碰撞。

地形进入这个问题的唯一入口是抬脚高度。平地 3–5 cm 够用；上 15 cm 的台阶要抬到 20 cm，并往前多留 5 cm 余量。高程图噪声 1–2 cm，抬脚高度至少取噪声的 3 倍，否则每一步都在赌。

凸 MPC：把未来一秒写成一个二次规划

这一节解决什么问题：把「未来 1 秒的平衡」写成一个 3 ms 内能解完的二次规划。

先把三个字母展开。模型预测控制（model predictive control, MPC）每个控制周期往后预测 1–2 s 的状态，解出一串控制量，只执行第一步，下一个周期拿新状态重新解一次。预测用的是模型（这里是 LIPM），所以「模型」；每一步都往前看一段再决定现在，所以「预测」。滚动执行是它和普通反馈的根本区别：反馈只看当前误差，MPC 看的是「按这个走法，1 s 后会到哪」。

为什么可以凸：LIPM 是线性系统；ZMP 在支撑多边形内是线性不等式；步长上下限是线性；力矩上限可以用 WBC 的可行域近似成线性。目标二次、约束线性，就是凸二次规划（Quadratic Programming, QP）。凸的好处不是优雅，是解唯一、时间可预测、不会在 1 ms 的预算里偶尔超时。

决策变量有三组：每个预测节点的状态 (ck, ck)、每个节点的 ZMP pk、未来 K 步的落脚点 sj。一个水平轴 16 个节点就是 32 个状态变量加 16 个控制量；两个轴加偏航，总变量 100–300 个。

预测时域取 1.0–1.6 s。1.6 s 够用的理由可以算：1.6/0.286 = 5.6 个时间常数，窗外的参考对当前决策的影响按 e−5.6 = 0.37% 衰减。图 6.4 用 1.6 s 窗与 6 s 窗分别反解同一条 ZMP 参考，质心轨迹最大差 1.04 mm——比 1 cm 的目标小一个量级。

离散化用零阶保持。A、B 不是拟合出来的：把 6.2 式的 t 换成 dt、把 p 当成一步内不变的常数，得到 c(dt) = p + (c − p)cosh(ωdt) + (c/ω)sinh(ωdt) 与 c(dt) = ω(c − p)sinh(ωdt) + ccosh(ωdt)。按状态 [c, c] 的系数逐项抄成矩阵：A 的四个元素是 cosh、sinh/ω、ω sinh、cosh，B 的两个元素是 1 − cosh 与 −ω sinh。ωdt = 0.35 时 cosh = 1.0619、sinh/ω = 0.1021——正是下面代码里的 1.062 与 0.102。代入 dt = 0.1 s、ω = 3.5：A = [[1.062, 0.102], [1.250, 1.062]]，B = [[−0.062], [−1.250]]。注意 B 的第一行只有 −0.062：ZMP 挪 1 cm，0.1 s 内只把位置推动 0.6 mm，却把速度推动 1.25 cm/s。ZMP 是加速度级输入，不是位置级——这解释了为什么 MPC 的状态里速度比位置更要紧。

写进 QP 的约束有四类。支撑多边形：pk ∈ P(phase_k)，单支撑时是脚下矩形，双支撑时是两脚凸包，每条边一条线性不等式。步长：0.10 ≤ |sj+1 − sj| ≤ 0.50 m。摩擦：|pk − ck| ≤ μ zc，μ = 0.6、zc = 0.8 时是 0.48 m——这条看着不像摩擦，推一下就是：水平加速度 a = ω²(c − p)，需要的摩擦系数是 |a|/g = |c − p|/zc，要求它不超过 μ，移项即得 |pk − ck| ≤ μ zc。力矩：τmin ≤ τ ≤ τmax，用 WBC 解出的可行域做线性化近似。

权重 Q 罚状态误差、R 罚 ZMP 偏离参考。Q 大，解更贴参考，ZMP 抖；R 大，ZMP 平滑，跟踪变慢。典型取 Q = diag(1, 0.1)、R = 0.01（量级），闭环时间常数落在 0.2–0.3 s。

求解器分两类：OSQP 是 ADMM 型，支持热启动与嵌入式代码生成；qpOASES 是 active-set，在小规模、热启动的问题上很快。人形带落脚点变量的 QP，变量 100–300、约束 300–800，单次 1–5 ms（量级估计）；四足纯接触力的版本报道过 <1 ms（Di Carlo 2018，0.5 s 视界）。重规划 20–100 Hz：OCS2 的腿式例程是 50 Hz MPC 加 400 Hz 跟踪。热启动用上一次的解做初值，时间约为冷启动的 1/3。

滚动执行只走第一步，下一周期用新状态重解。这里有个容易忽略的细节：解出的 p0 是给「决策时刻」的，但指令到关节要 30 ms——把状态按延迟外推 30 ms 再解，或者把整条解后移一个延迟。不补，30 ms 在 ω = 3.5 下相当于 10% 的相位误差，表现为持续的小幅前后晃。

工程经验 Field Note

MPC 的视界与重规划频率是两个独立的旋钮，别一起调。视界决定「能不能提前看到」，重规划频率决定「看到变化后多久改主意」。1.6 s 视界配 30 ms 重规划是常见组合；把视界拉到 3 s 只会让模型误差和接触序列的不确定性吃掉收益。

下面这段是伪代码，把一个水平轴的 MPC 从离散化写到求解，省略了另一轴、偏航、接触力分配与可行性恢复。重点看两处：A、B 是怎么从 cosh/sinh 来的，以及 Q、R 与四类约束各自对应什么物理量。

// 单刚体 MPC · 单轴 · 伪代码（省略另一轴、偏航、接触力分配）
// 状态 x_k = [c_k, cdot_k]（m, m/s）；控制 p_k = ZMP（m）
const double w = sqrt(9.81 / z_c);   // z_c=0.8 → w=3.50 rad/s
// ZOH 离散化（dt = 0.1 s）：
//   A = [[cosh, sinh/w], [w*sinh, cosh]]
//   B = [[1-cosh], [-w*sinh]] = [-0.062, -1.250]
Mat2 A = { { cosh(w*dt),     sinh(w*dt)/w },
           { w*sinh(w*dt),   cosh(w*dt)   } };
Vec2 B = { 1.0 - cosh(w*dt), -w*sinh(w*dt) };

// 目标：Σ (x_k - x_ref)^T Q (x_k - x_ref)
//      + (p_k - p_ref)^T R (p_k - p_ref)
// Q = diag(1.0, 0.1)：位置 1 m 与速度 1 m/s 的等价代价
//   Q 大 → 更贴参考、ZMP 更抖
// R = 0.01：ZMP 偏离参考的代价
//   R 大 → ZMP 更平滑、质心跟踪更慢
Mat2 Q = diag(1.0, 0.1);
double R = 0.01;

for (int k = 0; k < N; ++k) {   // N=16 步 × 0.1 s = 1.6 s
  // 1) 动力学：x_{k+1} = A x_k + B p_k
  // 2) 支撑多边形：p_k 属于 P(phase_k)
  // 3) 步长：0.10 <= |s_{j+1} - s_j| <= 0.50（m）
  // 4) 摩擦：|p_k - c_k| <= mu*z_c（mu=0.6 → 0.48 m）
  // 5) 力矩：tau_min <= tau <= tau_max（WBC 可行域）
}
solver.solve(qp, warm_start);   // 1-5 ms；热启动约 1/3
apply(p[0]);                    // 只执行第一步，下周期重解

与全身控制的分工

这一节解决什么问题：说清两个优化器各自吃什么、吐什么，以及接口错了会怎样。

MPC 的模型是 LIPM，两个状态，频率 20–100 Hz，输出未来 1 s 的质心轨迹、落脚点与参考接触力。WBC 的模型是全身 n+6 维，频率 1 kHz，输入是任务与接触序列，输出关节力矩。两者靠一个窄接口耦合：MPC 给 WBC 一组任务（质心加速度、姿态、摆动脚轨迹）与接触时序，WBC 返回可达性——力矩够不够、摩擦够不够。

如果 WBC 解不出，说明 MPC 的假设错了。这时只有两条路：降级（放弃手臂任务，保平衡）或者重规划（缩短步长、提前落脚）。把不可行当成「调权重」来处理，是分层架构里最常见的错误。

三个旋钮：步频、步长、抬脚高度

这一节解决什么问题：给你三个可调量，说清每个的收益和代价。

步频换稳定。1.25 步/秒 到 2.5 步/秒（单步周期 0.8 s 到 0.4 s），eωT 从 16.4 降到 4.06，同样的落点误差在一步内的放大倍数降到四分之一。代价在摆动腿：角速度正比于步频，惯性力矩正比于步频的平方；1.3 m 的机器人从 1.25 提到 2.5 步/秒，摆动腿峰值力矩约涨 3–4 倍（量级估计）。运输代价（Cost of Transport, CoT）通常在 1.2–1.5 步/秒 附近最低（量级判断），再快就是拿电换稳定。

步长换速度。v = S·f，步长翻倍速度翻倍。代价在踝上：ZMP 偏移正比于步长，踝力矩也正比于步长。60 kg 机器人把步长从 0.35 m 提到 0.55 m，需要的 ZMP 偏移从 0.10 m 到 0.16 m，超过踝的 0.10 m 权限，只能借髋关节和上身角动量，或者干脆改成跑。

抬脚高度换越障。代价是落地冲击：35 kg 的腿抬到 15 cm、摆动 0.25 s，落地垂直速度约 1.2 m/s；若 20 ms 内停住，冲击力 35×1.2/0.02 = 2100 N，约 6 倍体重。所以平地不会抬 15 cm——3–5 cm 够用，8 cm 是「有感知但不想付冲击代价」的折中。

三个真实系统：ASIMO、Atlas、Cassie

这一节解决什么问题：看三个真实系统怎么在同一组取舍上做不同选择。

ASIMO（Honda，2000–2011）走的是 ZMP 预览控制加在线步态生成，底层位置伺服。48 kg、1.30 m，2011 版标称 9 km/h。这样选的收益是确定、可解释、可重复：同一段楼梯走一万次，结果一样。代价是它假设 ZMP 被精确跟踪，地形和强扰动下适应差，2018 年项目终止。Kajita 2003 的预览控制是这条路线的方法论底座。

Atlas（MIT 与 Boston Dynamics，2016）走的是混合整数落脚点规划、质心 MPC、全身 QP 的分层优化。收益是非结构化地形和外力扰动下仍能走；代价是模型与标定要求高、算力大、调试链长。Kuindersma 2016 把这条链完整写了一遍：规划、MPC、WBC 与状态估计怎么接。

Cassie（Agility，2017）走的是另一条：离线优化一条周期轨道（虚拟约束），在线只做输入-输出线性化跟踪，落点用 DCM 修正。在线计算极省，步态自然，代价是换速度或地形要重算轨道。

一句话：ASIMO 用精确模型换可靠性，Atlas 用优化换鲁棒，Cassie 用离线算换在线省。三种选择今天都还在用，因为可靠性、鲁棒性和成本不可能同时按住。

本章要点 Takeaways

  1. 双足只有一个真正危险的方向。+ω = √(g/zc) 的发散模态；LIPM、ZMP、DCM 只是描述它的三套坐标，步态算法的差别在于什么时候用落点去兑换它。
  2. ZMP 是约束，不是判据。它必须落在支撑多边形内，但出界不等于摔——能不能救，取决于捕获点是否还能被下一步捕获。
  3. 1.6 s 的视界是算出来的。5.6 个时间常数之外的影响按 e−5.6 = 0.4% 衰减，与 6 s 窗的数值差 1.04 mm。
  4. 三个旋钮花的是同一种货币。步频换稳定、步长换速度、抬脚高度换越障，付的都是关节力矩与落地冲击。

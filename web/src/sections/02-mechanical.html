Mechanical Design

机械设计：自由度、连杆与关节模组

一台人形机器人有几个关节、每条腿多长、膝盖里装什么减速器，这三个问题决定了后面所有控制算法能做什么。这一章把「站住」翻译成关节角、雅可比与力矩：读完你能对着一张简图，手算单腿支撑时髋、膝、踝各要出多大力，并判断一个关节模组能不能胜任。

自由度账本：先决定关节数

这一节解决一个问题：一台人形机器人该有多少个关节，多出来的关节是资源还是负担。

自由度（Degree of Freedom, DoF）是一个独立运动轴。刚体在空间里有 6 个自由度（3 个平移加 3 个旋转）；脚的位姿也是 6 个数（3 个位置加 3 个姿态），每加一个关节只多一个可控方向，所以要让脚停在任意位置、摆出任意姿态，一条腿需要 6 个关节。分配是这样来的：髋 3 个负责大腿指向与绕大腿的旋转（roll 外展内收、pitch 屈伸、yaw 内外旋），膝只能屈伸所以 1 个（pitch），踝 2 个补脚掌的俯仰与侧倾（pitch、roll），合计 6 个。少于 6 个不是不能走，而是脚掌的姿态要由腿长和躯干姿态间接决定，落地时没法主动贴合地面；H1 就是每腿 5 个（踝只有 pitch），脚掌侧倾靠被动柔度，落地贴合差一些。

手臂的起点同样是 6 个：肩 3、肘 1、腕 2。实际产品在这里分档：Unitree G1 的单臂 5 个，手腕少一个轴，手掌不能独立于小臂定姿；H1 单臂只有 4 个（肩 3 + 肘 1，没有腕轴）；H1-2 加到 7 个（肩 3 + 肘 1 + 腕 3），手腕能绕小臂转。腰 1–3 个，颈 2 个。把账加起来：G1 是 12（双腿）+ 1（腰）+ 10（双臂）= 23，H1 是 10（双腿，每腿 5）+ 1 + 8（每臂 4）= 19，H1-2 是 12（每腿 6）+ 1 + 14（每臂 7）= 27、70 kg。G1 比 H1 多 4 个：腿多 2（踝 2 对 1）、臂多 2（5 对 4）；H1-2 比 G1 多 4 个，全在手臂上（7 对 5）。这三个型号的颈部都不计入（头固定或无颈自由度），所以 23、19、27 都不含颈；若按通用配置加颈 2 个，分别是 25、21、29，如图 2.1。

20–50 这个区间是两头挤出来的。往下，多数机型 12 个下肢关节是站稳的硬需求（H1 省到 10 个，用被动踝 roll 换轻量），上半身再少于 8 个，站和抓总得放弃一个；往上，每多一个关节就多一个 0.3–0.6 kg 的模组、一对走线、一份零位标定和一条限位。多 10 个关节大约多 3–6 kg，对 47 kg 的 H1 就是 6–13% 的体重，而这些重量大多长在远端，惯量代价比质量代价更大。

冗余自由度（redundancy）指关节数超过任务所需的那部分。它的价值只有一个兑现方式：零空间（null space）。零空间是不改变脚的位置、只改变关节角的自运动集合，n 比任务维数多几维，零空间就有几维。这件事的前提是你算得出雅可比——算不出，多余的关节就只是标定与走线的负担。G1 单臂 5 DoF 时，手掌姿态不能独立于肘，抓杯子要借腰转；这不是设计失误，是把成本让给了控制。

直觉 Intuition

把冗余想成「多出来的旋钮」：只有当你知道每个旋钮不影响手上的杯子时，多出来的旋钮才让动作更顺；否则你只是在盲拧。

坐标系与正运动学：把关节角变成脚的位置

这一节解决：给定一串关节角，怎么算出脚踩在哪里。

先固定三个坐标系。世界系 W 是右手系，z 向上、x 向前、y 向左，规划出来的落点与质心位置都在这里。机体系 B 的原点在骨盆的 IMU 上，同样 x 前 y 左 z 上，速度与加速度默认在 B 里表达。关节系跟着每根连杆走，关节角 q 按固定顺序排成向量：左腿 6 个、右腿 6 个、腰、左臂、右臂、颈。顺序必须写死，因为所有动力学库都按索引取关节。

正运动学（Forward Kinematics, FK）回答「角度到位置」。以一条平面两连杆腿为例：大腿长 L1、小腿长 L2，θ1 是髋的绝对角（从 +x 量起，向 z 下为正），θ2 是膝的相对角。平面坐标统一用 (x, z)：图 2.2 横轴是 x 前、纵轴是 z 下，式 2.2 与 2.3 也这么写；只有下面的代码块沿用 (x, y)，其中 y 就是这里的 z。每个关节对应一个齐次变换矩阵，末端位姿就是这些矩阵按顺序连乘——连乘的物理含义很朴素：先把大腿转 θ1，再在小腿自己身上叠加 θ2。

T(θ) = T1(θ1) · T2(θ2) · … · Tn(θn) · M 2.1

其中 M 是零位时末端的位姿。展开到平面上就得到两行：

x = L1 cos θ1 + L2 cos(θ1 + θ2)z = L1 sin θ1 + L2 sin(θ1 + θ2) 2.2

代入一组具体数：L1 = L2 = 0.30 m、θ1 = 58.4°、θ2 = 42.6°，得到足端 (0.10, 0.55) m、膝盖 (0.157, 0.256) m。手算校核一次：0.30 × cos 58.4° = 0.157，正是膝盖的 x。这类「算完代回去」的检查看起来幼稚，但它能在你写错一个正负号时立刻抓住。

通用串联链更常用指数积（Product of Exponentials, PoE）：每个关节存一个 6 维螺旋轴，末端 = exp([S₁]θ₁) … exp([Sₙ]θₙ) · M。这一段是进阶写法，初学可以先用式 2.1 的连乘、跳过这里：螺旋轴 = 转轴方向 + 轴上一点，exp([S]θ) 就是绕该轴转 θ 的齐次变换；它省掉了逐连杆建坐标系的麻烦，相邻轴平行时也不会出现 DH 参数退化（DH 在平行轴下参数不唯一，标定容易跳）。两套写法工程上都在用，Modern Robotics 的教材与代码是 PoE 的标准参考。

逆解：解析、数值与可达域

这一节解决：给定脚要踩的位置，怎么反算关节角；以及为什么同一个位置会有两组解。

两连杆有闭式解，工具是余弦定理：把髋、膝、足三点看成三角形，三边是 L1、L2 和 r（髋到足的距离），r² = x² + z²。解出膝角，再用两段 atan2 定髋角：

θ2 = ± arccos((r2 − L12 − L22) / (2 L1 L2))θ1 = atan2(z, x) ∓ atan2(L2 sin θ2, L1 + L2 cos θ2) 2.3

那个 ± 就是「膝盖朝前」与「膝盖朝后」两组解：脚在同一个点，膝盖可以在前面也可以在后面。配对规则：膝前解取 θ2 = +arccos(...)、θ1 用减号；膝后解取 θ2 = −arccos(...)、θ1 用加号，与下面代码的 knee_forward 分支一致。人的膝只能往一个方向弯，机器人靠机械限位与软件限位把另一组排除。切换分支时必须同时检查关节是否越限，否则控制器会在两组解之间跳变——现象是关节「抽一下」，而脚几乎没动。

目标可达。

解析解只对 2R、球腕这类结构存在。7 个自由度的臂、带闭链的踝、有耦合的腰都没有闭式解，工程上改用数值解：从当前关节角出发，反复解一个线性方程把末端误差往下压。直接用 J−1 在奇异附近会炸，所以加一个阻尼项 λ，变成阻尼最小二乘（Damped Least Squares, DLS）。下面这段代码把正解、解析逆解、雅可比、条件数与 DLS 放在同一组数上对账。

import math

L1 = L2 = 0.30                    # 大腿、小腿，单位 m
LIMIT = math.radians(10)          # 膝角小于 10° 视为接近奇异

def fk(t1, t2):
    """正解：返回足端与膝关节位置，单位 m。"""
    kx, ky = L1 * math.cos(t1), L1 * math.sin(t1)
    fx = kx + L2 * math.cos(t1 + t2)
    fy = ky + L2 * math.sin(t1 + t2)
    return (fx, fy), (kx, ky)

def ik(x, y, knee_forward=True):
    """解析逆解：r 超出 [|L1-L2|, L1+L2] 时返回 None。"""
    r2 = x * x + y * y
    if not (abs(L1 - L2) ** 2 <= r2 <= (L1 + L2) ** 2):
        return None
    c2 = (r2 - L1 * L1 - L2 * L2) / (2 * L1 * L2)
    t2 = math.acos(max(-1.0, min(1.0, c2)))      # 只取 0…π
    if not knee_forward:
        t2 = -t2
    t1 = math.atan2(y, x) - math.atan2(L2 * math.sin(t2),
                                       L1 + L2 * math.cos(t2))
    return t1, t2

def jacobian(t1, t2):
    """平面 2R：行是 x/y，列是 θ1/θ2，单位 m/rad。"""
    s1, c1 = math.sin(t1), math.cos(t1)
    s12, c12 = math.sin(t1 + t2), math.cos(t1 + t2)
    return [[-L1 * s1 - L2 * s12, -L2 * s12],
            [L1 * c1 + L2 * c12, L2 * c12]]

def det2(J):
    # 化简后 = L1·L2·sin θ2：奇异只由膝角决定
    return J[0][0] * J[1][1] - J[0][1] * J[1][0]

def kappa(J):
    """2×2 条件数：σ1σ2=|det|，σ1²+σ2²=‖J‖²，不需要 SVD。"""
    d = abs(det2(J))
    s = sum(v * v for row in J for v in row)
    if d < 1e-12:
        return float("inf")
    disc = max(0.0, s * s - 4 * d * d)
    s1 = math.sqrt((s + math.sqrt(disc)) / 2)
    s2 = math.sqrt((s - math.sqrt(disc)) / 2)
    return s1 / max(s2, 1e-12)

def dls_step(t1, t2, tx, ty, damping=0.05):
    """阻尼最小二乘一步：(JᵀJ + λ²I)Δq = Jᵀe。"""
    (fx, fy), _ = fk(t1, t2)
    J = jacobian(t1, t2)
    ex, ey = tx - fx, ty - fy
    a = J[0][0] ** 2 + J[1][0] ** 2 + damping ** 2
    b = J[0][0] * J[0][1] + J[1][0] * J[1][1]
    d = J[0][1] ** 2 + J[1][1] ** 2 + damping ** 2
    g0 = J[0][0] * ex + J[1][0] * ey
    g1 = J[0][1] * ex + J[1][1] * ey
    det = a * d - b * b
    return ((d * g0 - b * g1) / det, (a * g1 - b * g0) / det)

# 目标足端 (x, y)；代码里的 y 就是图 2.2 的 z（向下为正）
target = (0.10, 0.55)
t1, t2 = math.pi / 2, 0.3         # 故意给偏 30° 的初值
for _ in range(8):                # 数值解：不依赖解析式
    dt1, dt2 = dls_step(t1, t2, *target)
    t1, t2 = t1 + dt1, t2 + dt2

(fx, fy), _ = fk(t1, t2)
J = jacobian(t1, t2)
err = math.hypot(fx - target[0], fy - target[1])
print(f"θ1={math.degrees(t1):7.2f}°  θ2={math.degrees(t2):7.2f}°")
print(f"末端误差 {err * 1000:.3f} mm，|det J|={abs(det2(J)):.5f} m²/rad²")
print(f"条件数 κ={kappa(J):6.1f}" +
      ("  [警告] 接近奇异" if abs(t2) < LIMIT else ""))

运行结果是 θ1 = 58.40°、θ2 = 42.60°、误差 0.000 mm、κ = 6.5——数值解从偏 30° 的初值出发，8 次迭代收敛到解析解。这段代码有两处值得记住：条件数用 σ₁σ₂ = |det J| 与 σ₁² + σ₂² = ‖J‖² 这两个恒等式算，2×2 不需要 SVD；DLS 的阻尼 λ 在奇异附近把步长压小，代价是收敛变慢，这是「不炸」换来的。

所有可达足端位置的集合叫工作空间（workspace）。两连杆的可达域是一个圆环：外半径 L1 + L2，内半径 |L1 − L2|。L1 = L2 时内半径是 0，圆环退化成圆盘——腿能完全折叠，脚能碰到髋。图 2.2 把这台 0.6 m 腿的可达域、两条解的膝盖位置、以及 |det J| 的等值线画在一起。

雅可比：速度与力的同一张表

这一节解决：关节转一点，脚动多少；脚受一分力，关节要出多大力。

雅可比矩阵（Jacobian）J 把关节速度映射成末端速度，把末端力映射成关节力矩。同一个矩阵、转置一下，承担两件事：

x = J(q) q　　τ = J⊤(q) F 2.4

平面 2R 的 J 是 2×2，单位 m/rad。第一式是速度映射，第二式是力映射，两者互为对偶——这叫速度-力对偶（velocity-force duality）。所有阻抗控制、全身控制、以及后面第 5 章的 τ = J⊤F 估算，都从这张表出发。它对 2R 的行列式可以化简成一行：

det J = L1 L2 sin θ2 2.5

这个式子说明两件事。第一，奇异只由膝角决定，与髋角无关：腿伸直（θ2 = 0）或完全折叠（θ2 = 180°）时 det J 归零。第二，|det J| 在 θ2 = 90° 时取最大值 0.09 m²/rad²，在伸直时为 0。条件数（condition number）κ = σmax / σmin 把这件事量化：θ2 = 5° 时 |det J| 只剩最大值的 8.7%，κ ≈ 57；θ2 = 1° 时 κ ≈ 290。

κ 大不是数学上的不优雅，而是物理上的失控。足端在某个方向上的力臂趋近于零，同样的地面反力要几倍甚至无穷大的关节力矩；反过来，关节角的一点误差会被放大成很大的足端位置误差。腿伸直时最危险，正是因为它同时踩中这两条。

警告 Warning

别把「腿伸直」当成省力站姿。伸直时地面反力过膝，静态力矩确实最小；但 θ2 趋近 0 时足端沿腿方向的可控力也趋近 0，控制器算出的力矩指令会瞬间饱和，膝角一点扰动就能激出很大的角速度。设计上留 5–15° 屈曲，软件限位不要把 0° 写成可达值。

静力学：589 N 怎么变成 88 N·m

这一节解决：单腿支撑时，髋、膝、踝各要出多大力矩。

静力学就是把地面反力 F 通过 Jᵀ 映射回关节。工程上更好用的是杠杆臂形式：τ ≈ F·d，d 是地面反力作用线到关节轴的垂直距离。这个 d 由姿态决定，不由腿长决定——同样一条腿，蹲下去 d 变大，站直了 d 变小。

τknee ≈ Fz · d 2.6

算一个 60 kg 的例：单腿支撑时 Fz = 60 × 9.81 = 589 N。膝前伸 0.15 m，膝盖要 88 N·m；踝的 d 被足长锁死——脚长 0.24 m、压力中心最多前移到踝前 0.08 m，所以踝只有 47 N·m；髋在额状面 d = 0.10 m 时是 59 N·m。三个关节里膝最大，原因只有一条：它的力臂可以做到 0.15–0.20 m，踝不行。脚再长一点确实能增大力臂，但滚动会变差，落脚时也更容易绊。

静态值只是下限。走路时地面反力峰值约为体重的 1.1–1.3 倍，取 1.2：膝 106 N·m；再按峰值安全系数 1.5 选型，目标就是 160 N·m。这解释了产品页上的配比：35 kg 的 G1 把膝做到 90 N·m（EDU 版 120 N·m），够慢走与静态支撑；47 kg 的 H1 直接给 360 N·m，因为跑跳的冲击系数不是 1.2 而是 3–4：静态力臂只解释 1.9 倍（0.15 m 对 0.08 m），其余三倍多要靠冲击余量补上（量级推断）。

动力学直觉：惯量、刚度与小腿

这一节解决：为什么小腿要轻，为什么减速比不能随便加大。

惯量 I = Σ mᵢrᵢ²，r 是质量元到转轴的距离，平方项意味着远端质量最贵。算一个 60 kg 的例：小腿 2.4 kg、长 0.40 m、质心在膝下 0.18 m，也就是距髋 0.40 + 0.18 = 0.58 m，绕髋惯量约 2.4 × 0.58² + 0.03（自身绕质心项）≈ 0.84 kg·m²；大腿 6 kg、质心距髋 0.22 m，约 0.38 kg·m²。小腿质量只有大腿的 40%，却贡献了 69% 的摆动惯量（0.84 / 1.22）。换成更直白的说法：每 1 kg 放在小腿上，对髋惯量的贡献是放在大腿上的 6.9 倍（0.58² / 0.22²）。

走路时摆动腿要在 0.2–0.3 s 内完成一次前摆，髋要提供的角加速度在 20–40 rad/s² 量级。惯量大 10%，同一套增益下跟踪误差就大 10%，而控制器只能靠加大增益去补——增益又受结构谐振限制。这条链子上没有免费的补偿。

第二件事是反射惯量（reflected inertia）：电机转子经过减速比放大，折算到输出侧是

Jeff = Jm N2 + Jl 2.7

转子惯量 1×10⁻⁵ kg·m²、减速比 N = 100 时，Jeff 里电机那一项就是 0.1 kg·m²，与被驱动的小腿绕膝惯量同量级——按本章 XML 的 2.4 kg、质心在膝下 0.18 m 算，小腿绕膝约 0.11 kg·m²。它只是整条腿绕髋 1.22 kg·m² 的 8%，但对膝关节本身已经是必须计入的负载。膝盖撞到地面时，电机看到的是一个和腿差不多重的惯量，冲击直接进减速器。N = 9 时同一颗转子只贡献 8×10⁻⁴ kg·m²，这就是准直驱敢让人用手去拨的原因。

第三件事是结构刚度。连杆不是刚体，一阶弯曲频率必须比力控带宽高 2–3 倍，否则控制器会把结构谐振当成负载去激励。一根 0.40 m 长、外径 30 mm、壁厚 2 mm 的碳管，按悬臂梁估算一阶弯曲约 230 Hz（E = 70 GPa、ρ = 1600 kg/m³）；QDD 的力矩环带宽 100–300 Hz，两者只隔一倍，所以结构设计的目标很具体：别让 200 Hz 附近出现一个高 Q 的峰。

关节模组：五种传动，一张表

这一节解决：同样输出 100 N·m，为什么有的关节能用手反驱、有的不能。

一个关节模组等于五件东西：电机、减速器、编码器、驱动器，外加可选的力矩传感器或弹性元件。选型看四个数：峰值与连续力矩、转速、反射惯量、背隙与扭转刚度。表 2.1 是五种常见方案的量级对比。

表 2.1 五种关节传动方案的量级对比（′ = 角分，1′ = 1/60°；价格为单件量级估计）
类型 减速比 效率 背隙 / 精度 反驱透明度 成本 典型用途
谐波 50–160 65–85% 零背隙 1.5′ 差（柔度） $300–1200 肩、肘、腕
行星 3–10 90–97% 3–10′ 中 $80–400 膝、髋二级减速
摆线 20–120 80–90% 1–3′ 差 $200–600 重载关节
准直驱 QDD 6–10 80–90% 0.3–0.6° 好（可手拨） $150–400 腿的髋膝踝
串联弹性 SEA 30–100 60–85% 由弹簧决定 好（带宽低） $400–1500 协作臂、力控关节

谐波的卖点是精度：CSF-14-100 重复峰值 28 N·m、瞬时 54 N·m、重 0.52 kg，传动精度 1.5 arcmin。但它的瓶颈不是背隙而是柔度：扭转刚度 K1 ≈ 0.47×10⁴ N·m/rad，28 N·m 下扭 0.34°，而 19 bit 编码器折算到关节侧约 7×10⁻⁶°——两者差五个数量级。所以「零背隙 = 高精度」是伪命题，误差预算里柔度才是大头。

QDD 的卖点是透明：CubeMars AK80-9 是 9:1、9 N·m 连续 / 22 N·m 峰值、490 g，用手能拨动输出轴，力矩环带宽 100–300 Hz。代价是峰值电流大、铜损与温升成为瓶颈，连续力矩只有峰值的 40% 左右——站立不动比跑跳更容易过热：热看的是电流的均方根，站立时力矩小但一直通电，跑跳时峰值大但每步只有 30% 的时间在用力；连续力矩由散热决定，不由峰值决定（第 03 章给算例）。为什么现在流行 QDD：腿需要的是力控带宽与抗冲击，而不是减速比；把 N 从 100 降到 9，反射惯量降两个数量级，控制器的增益才敢往上开。

工程经验 Field Note

样机上量到的 0.3° 跟随误差，九成来自减速器柔度与连杆变形，不是编码器位数。先把刚度预算做出来，再决定 encoder 买 17 bit 还是 19 bit——顺序反了，钱花在最不重要的地方。

腿型、足端与结构工程

这一节解决：腿该多长、脚该多大、踝该怎么驱动，以及结构上哪些细节会让前面的计算全部作废。

大腿与小腿的长度比常见 1:1，各 0.40 m 左右，膝盖落在中间，工作空间对称、正逆解都好写。大腿明显长于小腿（1.2:1）利于跨障，但摆动惯量大；小腿过长则蹲不下去，髋的力矩需求也上来。0.9 m 腿长的机器人，站立时髋高大约 0.75–0.85 m，留 10–15° 膝屈曲。

足端有两种取向。点足是半径 5–10 mm 的球，没有踝的支撑力矩，靠点接触，控制简单、对地面不敏感，适合研究步态。平板足长 0.20–0.26 m，有支撑多边形，能站着不动、能缓慢重心转移，代价是踝要出力矩，落脚角度误差会直接变成冲击。人形多用平板足加橡胶底，橡胶与地面的摩擦系数 μ 在 0.6–1.0，低于 0.4 的瓷砖上，摩擦锥会先于力矩限幅约束住你。

踝的驱动分串联与并联。串联是两个电机都装在踝上，结构简单、行程大，但质量在远端；并联把电机放到小腿或髋部，用推杆或四杆机构传下来，远端只留连杆，摆动惯量小，代价是关节耦合、背隙与标定都更麻烦。Agility 的 Cassie 就把踝的驱动放在近端、用连杆传动，小腿上几乎没有电机。

结构材料在 7075-T6 铝与碳纤维之间选。7075-T6 屈服强度约 503 MPa、密度 2.81 g/cm³，好加工、好攻丝、能做金属嵌件；碳纤维密度 1.5–1.6 g/cm³，比刚度高 3–4 倍，但连接处必须加金属嵌件，否则螺栓会把孔压溃。拓扑优化能减 20–40% 的质量，前提是载荷工况写对：把「跌倒时单腿承受 3 倍体重」写进工况，否则优化出来的腿一摔就断。

剩下的都是细节，但每一条都能让前面的计算作废。走线：动态弯折半径至少 10 倍线径，弯折寿命 10⁶–10⁷ 次，绕不过去就加一个中间固定点。防护：关节 IP54 到 IP67，IP67 的代价是密封圈摩擦与散热变差。散热：连续力矩由铜损与外壳热阻决定，AK80-9 连续 9 N·m、峰值 22 N·m，长时间站立比跑跳更容易过热。装配与标定：关节零位、双编码器偏置、连杆长度要一起标——用三个已知足端位置就能把 L1、L2 与零位偏差一起解出来，比逐个量零件快得多。

工具链与三个真实取舍

这一节解决：从一张 CAD 图到能跑的仿真，最小闭环是什么；以及三家真实机器人的取舍。

先把角色分清：Onshape、SolidWorks 是 CAD，画零件与装配；URDF、MJCF 是描述连杆、关节、惯量的文件格式；MuJoCo、Isaac 是读这种文件做物理仿真的软件；RNEA 是递推牛顿—欧拉算法，用来算逆动力学、复核惯量。最小闭环是四步：CAD 里建装配（Onshape 或 SolidWorks）→ 导出 URDF 或 MJCF（onshape-to-robot 这类工具直接读装配约束）→ 在 MuJoCo 或 Isaac 里加载 → 用 RNEA 复核惯量。结构有限元（Finite Element Analysis, FEA）只算三个最危险的工况：单腿 3 倍体重、跌倒侧摔、急停。每一步都有验收项：总质量与 CAD 误差小于 5%，质心偏差小于 10 mm，足底穿透小于 1 mm，PD 站立 10 s 不摔。

惯量参数是链路里最容易糊弄、也最致命的一环：质量对、惯量错 10–20%，就足够毁掉全身控制与强化学习的实机迁移。MuJoCo Menagerie 里有 G1、H1、Apollo 的现成模型，拿它对账自己导出的数值，比对着 CAD 一格格抄快得多。

最后是三个真实取舍。Atlas 在 2024 年 4 月从液压改成全电：液压的力矩密度与抗冲击好，但效率低、密封与维护贵；电驱的带宽、能效与控制自由度更高，代价是散热与减速器寿命。Cassie 没有机械弹簧悬架，靠低减速比电机的反驱与连杆柔度吸收冲击，结构简单、成本低，代价是冲击直接进传动链，对编码器与减速器更狠。G1 走的是第三条路：35 kg、23 DoF、膝 90 N·m（2.6 N·m/kg），用低惯量内转子加交叉滚子轴承把成本压下来；H1 是 47 kg、膝 360 N·m（7.7 N·m/kg），静态需求只有 69 N·m，余下的都是跑跳余量。同一个厂的两档产品，差别不在控制算法，在力矩密度。

本章要点 Takeaways

  1. 自由度是预算，不是指标。多数机型 12 个下肢关节是站稳的硬需求（H1 用 10 个换轻量）；手臂 4、5 还是 7 决定作业能力；每多一个关节，多 0.3–0.6 kg、一对走线和一份标定。
  2. 逆解永远有两组，选哪组由机械限位决定。数值解必须拿上一帧做初值，否则会在膝前/膝后两个分支之间跳变。
  3. 腿伸直时静态力矩最小、力控最差。|det J| = L1L2|sin θ2|，膝角 5° 时只剩最大值的 8.7%，设计留 5–15° 屈曲。
  4. 选模组先看反射惯量与连续力矩。N = 100 的谐波把 1×10⁻⁵ kg·m² 的转子惯量放大成 0.1 kg·m²，与小腿绕膝的负载惯量（0.11 kg·m²）同量级；腿要力控选 N ≈ 9 的 QDD，臂要精度才用谐波。

08

Perception & Manipulation

感知、状态估计与操作：机器人的眼睛和手

前七章都建立在一个默认前提上：你知道自己在哪、脚有没有踩实、手该用多大的力。仿真里这三件事由物理引擎免费提供，真机上没有。这一章把它们补上，把开环的控制链闭合成环。

05 章的全身控制假设你手上有一组数：关节角、躯干姿态、脚在接触面上的位置。07 章的策略在仿真里学会了走，可它看到的机身速度、地形高度都是引擎直接喂的。真机上没有这种视角。60 kg 的机器人，姿态估计偏 1°，重力补偿的方向就偏 1°，等于给整机灌进 0.17 m/s² 的假水平加速度——比一个标定良好的加速度计零偏大 17 倍，2 s 就能让它凭空走出 0.3 m。

一个 1 mg 的零偏，十秒半米

这一节解决什么问题：算清「把 IMU 读数积分两次」为什么在十秒内就不可用，以及误差是怎么从一个常数长成一条抛物线的。

加速度计测的是比力（specific force）：静止放在桌上，它读 9.81 m/s² 而不是 0。扣掉重力之后，剩下的零点误差叫零偏（bias）。零偏不随运动变化，只随温度缓慢爬。误差的传播因此变成两次积分——速度误差是 b·t，位置误差是 ½b·t²。

Δv(t) = b t,　Δp(t) = ½ b t2 8.1

代入数字。b = 0.01 m/s²，也就是 1 mg，大约是消费级 IMU 标定后的残余零偏：10 s 后速度错 0.1 m/s、位置错 0.5 m；30 s 后 4.5 m；60 s 后 18 m。这条曲线不是「精度差一点」，是「完全不可用」——一台 1.3 m 高的机器人走出 18 m，早就撞上墙了。注意量纲：这是一次积分与二次积分的差别，速度线性增长，位置抛物线增长，所以时间越长，误差涨得越不成比例。图 8.1 把三种增长放在同一张坐标里。

陀螺更麻烦，因为姿态误差会反过来污染加速度。BMI088 这类 MEMS 陀螺的出厂零偏是 ±1 °/s，零偏温漂 0.015 °/s/K；板子开机后升 10 °C，零偏就漂 0.15 °/s。1 °/s 积分 60 s 是 60°，而 1° 的姿态误差在 60 kg 上就是 10 N 的水平力误差。姿态错，重力投影就错；重力投影错，水平加速度就错，再往后是速度和位置。这条回路本身没有负反馈，只能靠外部观测把它打断。

三个来源，三种错法

这一节解决什么问题：给每个传感器定一个位置——它擅长哪个频段、错在哪个方向——因为融合的本质是分工，不是投票。

惯性测量单元（Inertial Measurement Unit, IMU）是唯一能在 1 ms 内给出新信息的传感器：采样 200–1000 Hz，延迟小于 1 ms，0.1 s 内的角度和加速度都很准。它的错误集中在低频：零偏、温漂，以及积分带来的二次增长。换句话说，它知道「刚才发生了什么」，不知道「现在到底在哪」。

腿部里程计（leg odometry）用编码器和正运动学反推机体速度。逻辑是一条假设：支撑脚在世界系里不动，所以机体速度等于脚相对机体速度的反号，位置由髋到脚的向量与腿部雅可比算出。它每秒更新 50–500 次，误差是行程的 1–3%——走 10 m 差 10–30 cm。这个误差按里程长，不按时间平方长，而且完全没有零偏。它的死穴就是那条假设：脚打滑、腾空、踩在软地毯上，假设立刻不成立。

视觉惯性里程计（Visual-Inertial Odometry, VIO）给的是绝对量：看到的东西有纹理、有结构，可以认出「我来过这里」，所以误差不随时间累积。代价是延迟：相机 10–30 Hz 出图，VIO 输出可以插值到 200–400 Hz，但端到端延迟 10–30 ms，加上传输与特征提取，你拿到的常常是 40 ms 以前的世界。无纹理白墙、逆光、快速转动造成的运动模糊，会让它整段失效。

三者的错误在频域上是互补的：IMU 高频好、低频烂，里程计低频好、高频抖，视觉长期好、短期慢。融合要做的就是把它们各自的强项拼起来——但拼接之前，得先把高频那条路的积分算对。图 8.2 画出这三条支路进入融合器时的频率与延迟。

预积分（preintegration）就是干这件事的。两帧相机之间（30 Hz 就是 33 ms）有 13 个 IMU 采样；优化时相机位姿每变一次，如果从头重算这 13 次积分，代价随采样率线性涨；窗口里放 100 帧，就是 1300 次。预积分把这段积分提前压成一个增量与它的协方差，位姿变化时只做一次一阶修正，代价与采样率无关。式 8.2 前先把符号说清：ω̃ 与 ã 是陀螺和加速度计在采样点 k 的读数，bg 与 ba 是两者的零偏，Δt 是一个 IMU 周期；Exp 把三维旋转向量变成旋转矩阵，Π 与 Σ 分别是对采样点 k 的连乘与连加。三式从左到右分别积出两帧之间的旋转增量 ΔR̃、速度增量 Δṽ、位置增量 Δp̃，波浪号表示这是还没修正零偏的预积分量。

警告 Warning

预积分消掉的是重复积分，不是零偏漂移。它把「每帧重算 13 次积分」变成「一次增量加线性修正」，省的是算力；零偏仍在随机游走，出厂 ±1 °/s 不建模的话，1 s 就偏 1°。把预积分当成「消除漂移」的手段，是这一章最常见的一处误解——零偏必须进状态，由视觉或腿部里程计去观测它。

融合：预测与更新的两拍

这一节解决什么问题：把两个都不准的数合成一个更准的数，并且同时知道「这个数有多准」——因为下一层控制要用这个「多准」来决定出多大力。

扩展卡尔曼滤波（Extended Kalman Filter, EKF）把估计拆成两拍。预测拍：用 IMU 把上一时刻的状态推到这一时刻，协方差同时变大——因为推的过程有噪声，你变得更不确定。更新拍：来一个观测，按「谁更准就更信谁」的比例把预测拉向观测，协方差随之变小。比例就是卡尔曼增益。

K = P⁻H⊤(HP⁻H⊤ + R)−1x+ = x− ⊕ K(z − h(x−)),　P+ = (I − KH)P− 8.3

把符号定下来：H 是观测矩阵，把状态映射成观测——只测位置时 H = [1 0]；P⁻ 是预测之后的协方差（还没吃这个观测），R 是观测噪声的协方差，I 是单位阵；x⁻ 与 x⁺ 是更新前、更新后的状态，h(x⁻) 是按预测状态算出来的「应该看到什么」。三维时它们都是矩阵，一维时退化成三个数，下一段的算术就是退化后的版本。

一维算术最能说明问题。预测给出位置 ±10 cm（P⁻ = 0.01 m²），里程计报来一个 ±5 cm 的位置（R = 0.0025 m²）。K = 0.01/(0.01 + 0.0025) = 0.8，融合后的标准差是 10×5/√(10² + 5²) = 4.47 cm。两个各 ±10 cm 的独立观测融合后是 7.07 cm，正好是 1/√2。这就是协方差的用处：它不是误差，是不确定度；它既决定这一拍该信谁多少，也决定下一拍该信谁多少。

式中的 ⊕ 是流形上的加法，这一点要展开两层。第一层：姿态不能像位置那样三个数直接相加。用欧拉角描述姿态，在 ±90° 附近会奇异——两个轴重合，同一个姿态有无穷多组角，微分方程在那里没有唯一解，姿态误差也就无从定义。所以工程上把姿态误差写成「绕某个轴转多少度」这个三维向量，再用 Exp 把它变成旋转矩阵、右乘回原姿态：R ← Exp(δθ)·R，而不是矩阵逐元素相加。所有三维旋转构成的集合记作 SO(3)，它是个群——元素之间能相乘（连续转两次）、有单位元（不转）、每个元素有逆（反着转），流形指的就是这个集合本身弯曲、不能用一个平面坐标系覆盖。第二层：不变扩展卡尔曼滤波（Invariant EKF, IEKF）只是把这套加法定义得更一致——误差在机体坐标系里用同一套规则传播，滤波器不会因为机器人处在某个特定姿态就丢掉对某个方向的观测能力，也就是「可观测性一致」。反过来说，把欧拉角当成普通三维向量去加减、去插值，正是姿态估计最常见的实现错误。

接触：一条别人没有的观测

腿式机器人还有一条别人没有的信息：支撑脚在世界系里的速度为零。符号先说明白：v 是机体线速度，ω 是机体角速度，rf 是机体原点到支撑脚接触点的向量，Ri 是机体姿态矩阵，n 是观测噪声。括号里算的是接触点相对世界的速度，乘 Ri⊤ 把它投影回机体系；因为着地脚在世界系的速度为零，这三个分量就成了对 v 与 ω 的三条标量约束——这也是它比只报速度的里程计更值钱的地方。写成观测就是下面这条。

z = Ri⊤(v + ω × rf) = 0 + n,　n ~ N(0, Rzupt) 8.4

这条观测补上了 IMU 最缺的东西：IMU 只会说「加速度是多少」，不会说「没动」。零速更新（Zero Velocity Update, ZUPT）是它最朴素的形式，也是 1990 年代惯导在 GPS 失效时能撑住几分钟的原因。

关键在于：不能把它写成硬约束。因为「支撑脚不动」是假设，不是事实。接触判定有 5–30 ms 的窗口期，脚在落地瞬间会微滑 1–2 cm，踩在碎石或地毯上滑得更多。一旦写成 R = 0 的硬约束，滤波器会把「其实在滑」的那 2 cm 当成真实运动的反面灌进去，协方差瞬间坍缩到接近零；此后真出现 5 cm 的偏差，它要 100 倍的时间才肯重新相信观测——这叫过度自信。工程做法是写成带协方差的软观测，再用 χ² 门限剔除离群：一维 99% 门限 6.63，二维 9.21，三维 11.34。图 8.3 拆开了这 20 ms 的构成。

时间同步：20 ms 能毁掉什么

这一节解决什么问题：说清 20 ms 的时间错位如何在数值上变成落点误差，以及工程上怎么把它压到 1 ms 以内。

传感器来自三个时钟。IMU 在自己的采样中断里打时间戳，相机在曝光开始时打，编码器在总线帧里带。三个晶振不同、启动时刻不同，默认它们对齐的代价是 5–30 ms 的系统偏差——它不会随机抵消，会一直偏在同一个方向。

先算位置误差。1.5 m/s 的行走，20 ms 就是 3 cm。06 章算过：落脚点差 1 cm，一步之后发散运动分量差 7.9 cm。3 cm 的时间错位就是 3 倍的落点预算——不是「有点误差」，是「这一步必然要额外修正」。

再算相位。50 Hz 的控制环，20 ms 正好是一个整周期，相位损失 360°：延迟一拍的控制律看到的是上一拍的误差，符号都可能反。退到步频的尺度，2 Hz 时 20 ms 是 14.4°，5 Hz（跑步）时是 36°。一个设计成 40° 相位裕度的环，被延迟吃掉一半，阶跃响应就会振铃。

补法有三种，代价递增。硬件触发：相机曝光信号直接触发 IMU 采样，或用 PTP（IEEE 1588）把时钟同步到亚微秒，这是最好的，代价是布线与驱动支持。插值：把慢的传感器插到快的时刻上，姿态用球面线性插值（spherical linear interpolation, slerp），位置用线性；误差是 ½aΔt²，0.6 m/s² 的加速度、10 ms 间隔下只有 0.03 mm，可以忽略。外推：把估计推到「现在」，噪声放大 √(1 + τ/T)，τ = 20 ms、T = 5 ms 时放大 2.2 倍——延迟越大，外推越像赌博。

工程经验 Field Note

相机与 IMU 的时间偏移不要信标称值。让一个 LED 在相机视野里闪、同时把闪光接到 IMU 的同步引脚，比对两组时间戳——实测偏移常在 8–15 ms，标定后残差能到 1 ms 以内。同样的道理适用于足端力传感器：它的采样时刻和关节编码器差 1–2 ms，在 3 m/s 的摆动腿上是 3–6 mm 的位置错位，足够让落地检测早或晚一拍。

地形：把点云压成一张能踩的地图

这一节解决什么问题：把三维感知压成一张二维的「能不能踩」的地图，并算出「看多远才来得及停」。

高程图（elevation map）是最常用的中间表示：把地面切成 2–5 cm 的格子，每格存一个高度和一个方差。深度相机或激光点云按射线投射写进格子，GPU 上 10–30 Hz 能刷完 4 m × 4 m。存方差是关键——一格 2 cm 的高度和一格 8 cm 的高度，在代价函数里不该同权。

为什么不把点云直接交给规划：点云是三维的，点数随分辨率按面积涨，4 m × 4 m、2 cm 的格子就对应四万个位置，每次查询都要在几万个点里找邻域；压成 2.5D 的格子后，每格只有一个高度和一个方差，按坐标直接取，查询是 O(1)。代价是压扁会丢结构——桌子下面、悬空的横杆、两条腿之间的空隙，在单层高程图里都只能写成「地面」，要么上多层高程图，要么交给别的表示。

可通行性代价写成加权和：c = wh|Δh| + wsσ + wr·roughness，Δh 是相邻格高差，σ 是该格标准差，roughness 是局部曲率。权重不是调出来的玄学：wh 的量级由抬脚高度决定——抬脚 20 cm、留 5 cm 余量，所以 |Δh| > 0.15 m 的格子按常规步态判为不可通行；除非地形模块把它识别成楼梯并切到爬楼步态，那是另一套控制器。

台阶检测本质上是阶跃检测，难在信噪比。常见楼梯的踢面 0.15–0.18 m、踏面 0.25–0.30 m；高程图噪声 1–2 cm，15 cm 的踢面信噪比 7.5–15，随便一个阈值都能检出。真正难的是 3–5 cm 的路缘和地毯边：信噪比 1.5–3，和噪声同量级，检不出来就绊，检错了就原地停步。这就是为什么实机上「能上楼梯」和「能走人行道」是两个难度，图 8.4 把这两种情况画在同一段剖面里。

再看停步距离。从感知到停住，中间有三段时间：感知与规划延迟 τ、执行器响应、减速本身。合起来 d = vτ + v2/(2a)。取 τ = 0.15 s、a = 3 m/s²：1.5 m/s 需要 0.6 m，3 m/s 需要 2.0 m。所以前视距离不是「看到 1 m 就够」，而是「看到 1 m 之外还得留 0.6 m 刹车」；3 m/s 时前视至少 3 m，而 10 Hz 的高程图在 3 m/s 下每帧只前进 30 cm——漏掉两帧，前方就有 60 cm 从未被更新过。

SLAM：把漂移关进回环里

这一节解决什么问题：房间尺度上，「我在哪」不能靠积分，只能靠认出「这是哪」。

腿里程计 1–3% 的漂移，走 100 m 回到原点，差 1–3 m——足够让你以为自己在隔壁房间。同时定位与建图（Simultaneous Localization and Mapping, SLAM）就是处理这件事：一边建图，一边用图来定位。回环检测（loop closure）把误差一次压回 5 cm 量级：认出曾经来过的地方，把「现在的位姿」和「当时的位姿」连成一条边，整条轨迹一起重优化。

两条实现路线，差别在算力与可扩展性。滤波（EKF / IEKF）只保留当前状态与协方差，算力 O(1)，接触辅助的不变 EKF 能把状态压到 20 维量级，单核 CPU 跑到 IMU 频率；代价是线性化误差、不能回环，接触误判只能靠 χ² 检验补救。因子图（factor graph）把每帧位姿和每条观测都存成节点与边，回环时重优化窗口，10–50 ms 一次，代价是要做关键帧管理与内存控制。选型判据很硬：只要本体感知、算力紧，选 EKF；要跨房间、要回环、传感器异构，选因子图。

VILENS 是后者的代表：把腿部预积分速度因子、视觉、激光、IMU 放进同一个图，还额外估计一个「腿部速度偏置」——因为纯运动学在打滑时会系统性偏，不估这一项，视觉和腿会互相打架。这条经验值得记住：多传感器融合里，先问「哪个传感器有系统偏差」，再问「怎么加权」。

动态环境是另一个坑。办公室里有人走动，回环会把「人」当成地标，第二天人走了，地图就错了。DynaSLAM 用语义分割把人和车剔掉再建图。长期地图还要处理家具挪动：常见做法是保留多份子图，按当前观测选最匹配的一份，而不是每次重建。

操作：手上有多少力，比手在哪更重要

这一节解决什么问题：从「把手挪到某个坐标」升级到「把多大的力施加在哪个方向」。

抓取位姿（grasp pose）是一个 6 维量：3 维位置加 3 维姿态。对平行夹爪，最稳的是反对跖抓取（antipodal grasp）：两个接触点的法线共线且相向，夹紧力只产生法向力，不产生让物体转动的力矩。夹持力有下限：2 kg 的杯子、摩擦系数 0.5，每指至少要 19.6 N；取 2 倍安全系数就是 40 N，落在常见夹爪 20–200 N 的行程里。低于这个数，加速度一上来物体就打滑。

力控的核心是阻抗（impedance）：不指定位置，而指定「位置偏差对应多大的力」。位置是结果，刚度才是指令。

τ = J⊤[Kp(xd − x) + Kd(xd − x) + Fff] + g(q) 8.5

Kp 的选择是安全与精度的兑换。拎 2 kg 的负载需要 19.6 N：Kp = 2000 N/m 时下垂 1 cm，位置很准，但末端意外撞到人 5 cm，就是 100 N——相当于挂上 10 kg 的重物；Kp = 200 N/m 时下垂 10 cm，同样的 5 cm 侵入只有 10 N。装配任务要前者，人机共处要后者；实机上常用变阻抗：接近时软，接触后硬。

力控带宽比位置环低一个量级。电流环 20 kHz、关节力矩环 1 kHz，但末端力控通常只有 100–1000 Hz：串联刚度、减速器背隙、滤波器的相位都把带宽吃掉了。这就是为什么「轻拿轻放」比「准确定位」难——你要控的量，恰恰是被机械结构滤掉的那部分。

双臂与全身：接触点不止在手

双臂协调多两个约束：两臂末端的相对位姿要固定，否则物体被拧；内力要显式控制。两台 7 自由度臂各用 50 N 对推一个盒子，盒子受的净力是 0，但内力是 100 N——足以把 2 kg 的纸箱压瘪。所以双臂控制器要同时解「相对位姿」和「内力分配」两组任务，这也是 05 章分层 QP 最典型的用武之地。

全身操作（whole-body manipulation）把接触点从手扩展到全身：用肩顶、用胯靠、用前臂压。推一个 20 kg 的箱子，地面摩擦 0.5，需要 98 N 的水平力；机器人自身 60 kg、同样摩擦，能出 294 N，够用。但接触点高 1.2 m 时，98 N 产生 118 N·m 的倾覆力矩，必须把质心前移或让后脚蹬地——问题又回到 05、06 章的 WBC 与 ZMP。

遥操作：既是产品，也是数据源

这一节解决什么问题：说清人现在为什么还在环路里，以及人怎么把「手感」变成能训练的数据。

四种输入方式，差别在带宽和力反馈。VR 头显（Apple Vision Pro 一类）用头部 6 自由度加手部追踪，手部 30–90 Hz，无遮挡时精度 1–2 cm；光学动捕 100–240 Hz、毫米级精度，但要一屋子相机；外骨骼能一对一映射关节角并回传力，成本最高；主从臂（ALOHA 式）最土也最有效——操作者直接握住从臂，力和位姿天然对齐。

延迟是硬指标。人对 100 ms 以内的延迟可以适应，超过之后开始出现「犹豫—过冲」：先推一点、看没反应、再推、然后收。这段动作会被原样录进示教数据，策略学到的不是任务，是操作者的手抖。这是「数据质量」里最容易被忽略的一条：录数据时先量端到端延迟，再谈采多少条。

遥操作既是产品也是数据源。产品侧：Figure、1X 都公开演示过人在环路里兜底——机器人卡住的瞬间人接管几秒，处理完再交还。数据侧：ALOHA 用主从臂采 50 条示教，就能训出 80–90% 成功率的精细双臂任务；Open-TeleVision 用立体视觉加手部映射，在两种人形上采长程任务。没有遥操作，就没有下一节的模仿学习。

模仿学习与 VLA：动作块是分水岭

这一节解决什么问题：示教怎么变成策略，以及为什么「一次预测一段动作」是这条路上真正的分水岭。

最直接的做法是学一个映射 π(at | ot)：看到什么，出什么动作。两个问题立刻出现。每条示教只有几百个样本点，逐帧学必然过拟合；单帧观测也不足以判断动作的相位——同一张图，可能是「伸手」也可能是「收回」。动作块（action chunking）把这两件事一起解决：一次预测未来 H 步，只执行前 k 步，然后重规划。

πθ(at:t+H | ot),　执行 at:t+k,　k < H 8.6

H = 100、控制 50 Hz 就是 2 s 的动作；k = 50 就是 1 s 的开环执行。这把「策略要多快」和「动作要多细」解耦了：策略可以慢，动作依然连续。ACT 就是靠这一招在 50 Hz 的真机上跑 CVAE 加 Transformer：每个任务 50 条示教、每条 8–14 s、合计 10–20 分钟，六个任务成功率 80–90%。

扩散策略（Diffusion Policy）换了一个角度：把动作分布建模成去噪过程，能表达多峰——同一个杯子，从左抓和从右抓都对，逐帧回归会把两者平均成一个抓不到的位置。代价是推理要迭代 10–100 步，频率比 ACT 低一个量级。选型判据：低成本硬件、要高频闭环，选 ACT；多模态示教、能接受低频，选扩散。

从动作块到 VLA

再往上是视觉-语言-动作模型（Vision-Language-Action, VLA）：把图像和语言直接映射到动作，借视觉语言模型的语义先验。RT-2 把动作离散成文本 token，和语言共享同一个头，55B 版本在 6000 次试验里表现出「把石头当锤子」这类迁移，但自回归推理只有 1–3 Hz。π0 换成 3.3B 的视觉语言模型加 300M 的动作专家，用流匹配（flow matching）直接回归连续动作块，最高 50 Hz。GR00T N1 把这件事拆成两级：2.2B 的模型里，System 2 跑 10 Hz 做语义推理，System 1 跑 120 Hz 出动作，在 L40 上用 bf16 采 16 步动作块耗时 63.9 ms。图 8.5 把这四层的决策周期放在同一根对数轴上。

这一段里有四个词值得拆开。token 是语言模型的基本单位：RT-2 把每个动作维度离散成 256 个区间（bin），一个 bin 就是一个 token，动作于是变成了「句子」。55B 指 550 亿参数，B 就是 billion。流匹配就是 π0 用的那一套：学一个把噪声逐步搬成动作序列的速度场，一次生成整段连续动作块，不必像自回归那样一个 token 一个 token 地往外吐。bf16 是 bfloat16，16 位浮点：指数范围与 fp32 相同、尾数只有 7 位，省显存也省带宽，代价是精度低一些。

警告 Warning

VLA 的涌现能力是定性观察，不是可靠性指标。RT-2 的「拿石头当锤子」出自 6000 次试验里的个案，同一模型在未见物体上的成功率会低一个档次。判断一个 VLA 能不能上线，看三件事：在你的物体上成功率多少、失败时会不会安全停下、单次推理延迟是否短于动作块的长度——三条缺一条，它就只是个演示。

三个真实系统：Atlas、Figure 02、Optimus

这一节解决什么问题：看三个公开系统怎么在这三件事上取舍，以及哪些结论能从公开资料里确认、哪些不能。

Atlas。2015 年 DRC 版本的 Atlas 头部装了激光雷达与多目相机，Kuindersma 等 2016 年公开的栈里，状态估计以 IMU 加腿部运动学打底、激光与视觉做定位修正，控制是模型预测加全身 QP。2024 年 4 月波士顿动力换成全电 Atlas，公开演示里能看到头部一圈传感器，但算法细节没有论文公开——任何声称确切知道它用哪种滤波器的说法都是猜的。能确认的只有架构：本体感知跑高频、外部感知跑低频、模型预测在中间。

Figure 02。公开演示的重点不是行走，是对话：人说一句，它隔 1–2 s 开始动作，中间隔着语音识别、大模型推理、任务分解、技能调用四层。这条链路的频率是 1 Hz 量级，和 1 kHz 的伺服差三个数量级，所以它必须待在频率阶梯的最顶端，把具体动作交给下面的技能库。这也是所有「会说话的人形」的共同架构：语言模型不产生力矩，它只选技能。

Optimus。公开表述是纯视觉：不用激光雷达，靠多目相机加神经网络，与 FSD 同源。纯视觉的代价可以用视差公式算清楚：σz ≈ z2σd/(f·b)。f = 500 px、基线 b = 0.12 m、视差误差 0.2 px 时，1 m 处深度误差 3 mm，3 m 处 3 cm，5 m 处 8 cm。8 cm 已经超过半个踢面——所以纯视觉在操作距离（0.5–1.5 m）内绰绰有余，在导航距离（5 m 外）必须靠地图与记忆补。这不是「视觉行不行」的问题，是「在哪个距离上行」的问题。

一段伪代码：预测、更新、门限

这一节解决什么问题：把前面的公式落成三十行能读的代码，看清每个矩阵在做哪件事。

下面是一维（垂向）EKF 的伪代码，省略了姿态流形、腿部雅可比和零偏的随机游走——那些在三维版本里各占十几行。它保留了三个关键动作：用 IMU 预测、用里程计位置更新、用接触标志决定要不要做零速更新，以及一道 χ² 门限。

# IMU + 腿部里程计 + 零速更新的 EKF（伪代码，一维垂向）
import numpy as np

dt   = 0.0025                  # IMU 周期 400 Hz
x    = np.array([0.0, 0.0])      # 状态 [位置 p, 速度 v]，m 与 m/s
P    = np.diag([1e-4, 1e-4])   # 初始不确定度：位置 ±1 cm、速度 ±1 cm/s
Qa   = 0.05**2 * dt             # 加速度计噪声谱密度，m²/s³
R_leg, R_zupt = 0.03**2, 0.02**2   # 位置 ±3 cm、零速 ±2 cm/s

def predict(x, P, acc):
    F = np.array([[1.0, dt], [0.0, 1.0]])
    B = np.array([0.5 * dt * dt, dt])
    x = F @ x + B * acc                    # 用 IMU 推一步
    P = F @ P @ F.T + Qa * np.outer(B, B)  # 协方差只会变大
    return x, P

def update(x, P, z, H, R):
    y = float(z - H @ x)              # 新息：观测减预测
    S = float(H @ P @ H.T) + R
    if y * y / S > 6.63:            # χ² 门限 99%，1 自由度
        return x, P                     # 判为离群：宁可不用，也别污染协方差
    K = (P @ H.T) / S                 # 卡尔曼增益：谁准信谁
    x = x + (K * y).ravel()
    P = (np.eye(2) - K @ H) @ P
    return x, P

H_P = np.array([[1.0, 0.0]])            # 观测到位置
H_V = np.array([[0.0, 1.0]])            # 观测到速度

for k in range(int(10.0 / dt)):
    x, P = predict(x, P, imu.read_accel())       # 已扣重力、已扣标定零偏
    if k % 8 == 0:                            # 50 Hz：里程计给位置
        x, P = update(x, P, leg_odom.position(), H_P, R_leg)
    if foot_force[k] > 50.0:                  # 判为支撑相才敢做零速更新
        x, P = update(x, P, 0.0, H_V, R_zupt)

读这段代码要盯住三处。第一，P 在预测里变大、在更新里变小，这个「呼吸」就是滤波器的工作节奏；如果 P 不呼吸，说明 Q 或 R 写错了。第二，零速更新只在 foot_force > 50 N 时执行——这条判断本身就是第 3 节讲的接触检测，它错一次，滤波器就被灌进一次假信息。第三，χ² 门限放在更新内部：先怀疑观测，再决定要不要降低 P，这个顺序反了就会过度自信。

力控那一侧只有十行，但同样有一个必须做对的细节：限幅。超限的力矩指令在仿真里只是「不理想」，在真机上就是一次失控。

// 1 kHz 笛卡尔阻抗 + 重力补偿（伪代码，省略雅可比伪逆与奇异处理）
Eigen::Vector3d e  = x_d  - x;                  // 位置误差，m
Eigen::Vector3d ed = xd_d - xd;                 // 速度误差，m/s
Eigen::Vector3d F  = Kp.cwiseProduct(e)         // Kp = 2000 N/m（装配）
                   + Kd.cwiseProduct(ed)        // Kd = 60 N·s/m
                   + F_ff;                      // 前馈力，抵消负载
tau = J.transpose() * F + g(q);                 // 关节力矩，N·m
tau = tau.cwiseMax(tau_min).cwiseMin(tau_max);  // 限幅：超限就是失控

把环闭上

这一节解决什么问题：把这一章的六件事折回一条链路，看清每一件的输出交给谁。

状态估计输出 (p, v, R, b)，交给 05 章的 WBC 当反馈；接触标志同时进状态估计和力分配；高程图输出可通行性与落脚候选，交给 06 章的落脚规划与 MPC；阻抗控制输出关节力矩，走 04 章的 1 kHz 接口；VLA 输出动作块，落在频率阶梯的最顶端。缺任何一环，下游都在用错的数算对的公式。

本章要点 Takeaways

  1. 纯积分是抛物线，不是直线。0.01 m/s² 的零偏 10 s 就是 0.5 m、60 s 是 18 m，所以 IMU 永远只能做「短时真相」，长时真相必须由外部观测给。
  2. 融合是分工，不是投票。IMU 管高频、里程计管低频、视觉管绝对；协方差决定权重，把接触写成零协方差的硬约束会让滤波器过度自信，滑一次就恢复不过来。
  3. 先把时钟对齐，再谈滤波。20 ms 在 1.5 m/s 下是 3 cm，是 06 章落点预算的 3 倍；标定一次相机—IMU 偏移能把它压到 1 ms 以内，性价比高于换任何算法。
  4. 操作的门槛是力不是位置，策略的门槛是频率不是参数。Kp 从 2000 降到 200 N/m，同样的 5 cm 侵入从 100 N 降到 10 N；ACT 用 50 条示教在 50 Hz 上跑到 80–90%，靠的是动作块而不是更大的网络。
